# 汎用学習クイズサイト 要件定義書

## 1. 概要

本サイトは、授業資料・小テスト・予想問題をもとに、一問一答形式で学習できるスマホ対応クイズサイトである。経済学以外の科目にも流用できるよう、問題データを共通形式へ変換して読み込む構成にする。

サイト本体は抽出元の形式を意識しない。小テスト、PDF、スライド、手入力データなどは、公開前のビルド作業で共通の問題データ形式へ正規化し、`QUESTION_DATA` または `PREDICTED_QUESTION_DATA` として読み込む。

## 2. 対象ユーザーと利用シーン

- 対象ユーザー: 授業小テストや試験対策をスマホで反復学習したい学生。
- 主な利用シーン:
  - 小テストの復習。
  - 授業スライドから作った予想問題の演習。
  - 通学中や空き時間の一問一答。
  - ホーム画面に追加したPWAでのオフライン学習。

## 3. 主要機能

- 一問一答モード
  - 問題を1問ずつ表示する。
  - 選択、複数選択、対応問題、入力問題、自由記述に対応する。
  - 選択・入力後に「判定する」を押して正誤を確定する。
- 一覧モード
  - 全問題を一覧で確認できる。
  - 問題文、選択肢、答えをまとめて確認できる。
- フィルター
  - 問題区分: 小テスト問題 / 予想問題
  - 範囲: 第1回、第2回、単元名など
  - 形式: 選択 / 複数選択 / 対応 / 入力 / 自由記述
  - 進捗: 未着手 / 習得 / 復習
- 学習補助
  - シャッフル出題
  - 答えを見る
  - 分かった / 復習マーク
  - 検索
- スマホ対応
  - レスポンシブ表示
  - PWA対応
  - ホーム画面追加
  - オフライン利用

## 4. デザイン仕様

- 全体方針
  - スマホで片手操作しやすい学習カード型UIにする。
  - 装飾よりも読みやすさと操作しやすさを優先する。
  - 授業・試験対策用なので、落ち着いた配色にする。
- レイアウト
  - PCでは左にフィルター、右に問題カードを配置する。
  - スマホではフィルター、操作バー、問題カードを縦並びにする。
  - 問題カードは1問に集中できるよう、余白を広めに取る。
- ヘッダー
  - サイト名を表示する。
  - 総問題数、習得数、復習数を表示する。
- フィルター
  - ボタン型のチップUIにする。
  - 選択中のフィルターは色で強調する。
  - 問題区分、範囲、形式、進捗を分けて表示する。
- 問題カード
  - 上部に範囲名、問題区分、形式、現在位置を表示する。
  - 問題文は改行を保持して表示する。
  - 画像がある場合は問題文の上に表示する。
- 選択肢
  - タップしやすい大きさのボタンにする。
  - 選択中の選択肢は背景色と枠線で強調する。
  - すべての問題形式で、選択・入力後に「判定する」ボタンで確定する。
- 正誤表示
  - 正解時は緑系、不正解時は赤系で表示する。
  - 不正解時は正解を表示する。
- 操作ボタン
  - 前へ、次へ、答えを見る、分かった、復習を配置する。
  - スマホではボタンが横に詰まりすぎないよう折り返す。

## 5. 問題データ読み取り仕様

### 5.1 基本方針

問題データは、どの科目でも最終的に共通のJSON形式へ変換して読み込む。入力元は3種類に対応する。

- 手入力データ
- 小テストHTML / `.webarchive`
- PDF / スライド資料

サイト本体は問題抽出を行わない。抽出・変換は公開前のビルド作業として行い、生成済みの `QUESTION_DATA` と `PREDICTED_QUESTION_DATA` だけをサイトが読む。

### 5.2 Data Flow

1. 元データを用意する。
   - 小テスト: `.webarchive` / HTML
   - 授業資料: PDF / スライド
   - 手作成: JSON / CSV / Markdown表
2. 抽出スクリプトで本文・選択肢・解答・画像を取得する。
3. 共通問題形式へ正規化する。
4. `questions.js` または `predicted_questions.js` として出力する。
5. サイト起動時にJavaScript配列として読み込む。

### 5.3 小テスト問題の読み取り

- `.webarchive` からHTML本文を取り出す。
- `checked`、`selected`、入力欄の `value` から正解を抽出する。
- 問題形式の変換ルール:
  - radio: `single`
  - checkbox: `multiple`
  - 対応問題: `matching`
  - 入力欄: `text`
  - textarea: `free`
- HTML内画像は `assets/` に保存し、問題の `images` に紐づける。
- 問題文はHTMLから不要な採点表示やスクリプトを除去し、本文だけに正規化する。

### 5.4 予想問題の読み取り

- PDFからテキストを抽出する。
- スライド内の `（ ）`、重要語句、まとめページ、小テスト既出形式を参考に問題化する。
- 自動抽出だけでなく、内容理解による補正を前提にする。
- 最終的には人が確認したうえで `PREDICTED_QUESTION_DATA` に入れる。
- 予想問題の `category` は `prediction` とする。

### 5.5 手入力問題の読み取り

- 他科目で使う場合の基本形式。
- 直接JSON形式で問題を追加できるようにする。
- Excelやスプレッドシートから作る場合も、最終的には同じJSON形式へ変換する。
- 手入力問題でも、問題区分・範囲・形式・画像の扱いは共通仕様に従う。

## 6. 共通問題データ仕様

問題はJavaScript配列として管理する。小テスト問題は `QUESTION_DATA`、予想問題は `PREDICTED_QUESTION_DATA` に入れる。

```js
{
  id: "subject-unit-001",
  source: "第1回",
  category: "quiz",
  number: 1,
  prompt: "問題文",
  answer: "正解",
  type: "single",
  choices: ["選択肢A", "選択肢B"],
  images: []
}
```

項目定義:

- `id`: 問題ごとの一意ID。
- `source`: 範囲名。例: `第1回`, `英単語 Unit 1`
- `category`: `quiz` または `prediction`
- `number`: 範囲内の問題番号。
- `prompt`: 問題文。
- `answer`: 正解。
- `type`: 問題形式。
- `choices`: 選択肢。
- `images`: 画像パス配列。

## 7. 問題形式

- `single`
  - 単一選択。
  - 1つ選択してから「判定する」で確定する。
- `multiple`
  - 複数選択。
  - 正解は ` / ` 区切りで記述する。
- `matching`
  - 対応問題。
  - 正解は `① = 用語 / ② = 用語` 形式。
  - 選択肢は `a: 用語` 形式。
- `text`
  - 入力問題。
  - 入力値と正解を比較して判定する。
- `free`
  - 自由記述。
  - 原則として自動判定ではなく、模範解答確認用に使う。

## 8. サンプル

単一選択:

```js
{
  id: "math-1-1",
  source: "第1回",
  category: "quiz",
  number: 1,
  prompt: "需要曲線は誰の行動を表すか。",
  answer: "消費者",
  type: "single",
  choices: ["消費者", "生産者", "政府"],
  images: []
}
```

対応問題:

```js
{
  id: "econ-1-2",
  source: "第1回",
  category: "prediction",
  number: 2,
  prompt: "①から③に当てはまる語句を選びなさい。",
  answer: "① = 消費者余剰 / ② = 生産者余剰 / ③ = 総余剰",
  type: "matching",
  choices: ["a: 総余剰", "b: 生産者余剰", "c: 消費者余剰"],
  images: []
}
```

複数選択:

```js
{
  id: "civics-1-3",
  source: "憲法",
  category: "quiz",
  number: 3,
  prompt: "国会の権限として正しいものをすべて選びなさい。",
  answer: "法律の制定 / 予算の議決",
  type: "multiple",
  choices: ["法律の制定", "予算の議決", "条例の制定", "地方税率の決定"],
  images: []
}
```

入力問題:

```js
{
  id: "english-1-4",
  source: "Unit 1",
  category: "prediction",
  number: 4,
  prompt: "次の日本語に対応する英単語を入力しなさい: 需要",
  answer: "demand",
  type: "text",
  choices: [],
  images: []
}
```

## 9. Validation

- `id` が重複していないこと。
- `prompt` と `answer` が空でないこと。
- `type` が対応形式のいずれかであること。
- `category` が `quiz` または `prediction` であること。
- `single` / `multiple` は `choices` が空でないこと。
- `matching` は `answer` が `① = 用語 / ② = 用語` 形式であること。
- `images` に指定した画像ファイルが存在すること。
- 小テスト問題と予想問題が同じUIで判定できること。

## 10. 公開・利用要件

- GitHub Pagesで公開できる静的サイトとする。
- サーバーやデータベースは不要。
- PWAとしてホーム画面に追加できる。
- 一度読み込んだ後はオフラインでも利用できる。
- 進捗はブラウザの `localStorage` に保存する。

## 11. 他科目化の手順

1. 科目名に合わせてタイトルを変更する。
2. 元データを用意する。
3. 小テスト、PDF、手入力データを共通問題形式へ変換する。
4. `source` に単元名や授業回を入れる。
5. `category` で小テスト問題と予想問題を分ける。
6. 必要に応じて画像を `assets/` に追加する。
7. Validation項目を確認する。
8. GitHub Pagesに公開する。
9. スマホで開き、ホーム画面に追加する。

## 12. 対象外

- ログイン機能
- ユーザー間の進捗同期
- サーバーDB
- 成績提出
- 複雑な記述式採点
- App Store / Google Play 配布
- サイト上でのPDFアップロードと自動問題生成

## 13. 受け入れ条件

- 小テスト問題と予想問題を切り替えられる。
- 範囲別に問題を絞り込める。
- 5種類の問題形式が動作する。
- すべての問題形式で「判定する」を押して正誤が確定する。
- スマホで問題が解ける。
- 正誤判定が表示される。
- 習得/復習の進捗が保存される。
- GitHub Pages上で公開できる。
- ホーム画面追加後、オフラインでも利用できる。
